Cairn & Belay's full write-up

Reminders catch, Trello tracks, Obsidian remembers

A personal AI system for my job search. Designed and directed by me, coded by Claude Code, built over two days in September 2026.

In short

I'm a History graduate working in outdoor retail while applying for graduate roles. My to-dos were spread across Apple Notes, Reminders and two inboxes, and the job-alert emails I'd signed up to were burying the ones that mattered. I designed a system that gives every task and note one home, flags test and interview invitations within 15 minutes, and writes me a briefing each weekday morning.

I'm not a developer. I made the design and security decisions; Claude Code wrote the code and explained each part until I could follow it.

  • Built in: two days (25-26 Sept 2026)
  • Code: about 600 lines (a Python background script and a small JavaScript mail reader)
  • Running cost: the frequent jobs use no AI at all; Claude runs once a day
  • First run: 226 emails from the previous fortnight sorted into 4 tasks and 22 application updates

The problem

  • My tasks were scattered across several notes and reminders apps, with no structure.
  • Job alerts flooded my inbox, so assessment invites and interview requests were easy to miss. The first scan of my inbox turned up a graduate scheme I'd meant to apply to and forgotten. I applied that day.
  • Claude Chat and Claude Code don't share memory, and every new chat starts blank.

Where it started

I'd found a published design for a Claude "memory system": a search engine over memory files, hourly inbox checks, around 870 lines of code. I asked Claude Code to assess it against my situation. We kept the good ideas (plain text files as the source of truth, a daily briefing, draft but never send) and dropped the rest. The search engine solved a problem of scale I don't have. The hourly checks would have used up my plan. And an AI that reads your whole inbox every hour and can rewrite its own memory is an easy target for attack.

Design principles

Agreed at the start and used for every decision since:

  1. Start from the problem, not the tool. "My tasks are scattered" came before "use Obsidian".
  2. One job per app, so nothing lives in two places.
  3. Cheap, dumb and frequent; smart and rare. Plain scripts do the constant checking for free. Claude does the thinking once a day.
  4. Test before switching on. Every script ran in a "dry run" mode first, showing what it would do without changing anything.
  5. Anything permanent needs my OK.
  6. Write it all down in plain English, so I can understand, maintain and question it.

When the background script spots an invitation to a test, interview or assessment, it shows a Mac notification and creates a reminder, so my phone pings within a minute. It's simple word matching, not AI. Tested against two weeks of real mail, it flagged all six genuine next steps plus one panel invitation, and skipped every rejection.

The morning task sorts mail into five groups: needs action (a Trello card), application updates (the applications log), people on live projects, job alerts (three best picks at most) and noise.

What broke, and how we fixed it

  • A missed alert. The first version only read the last 24 hours of email, and an assessment invite slipped through. It now reads everything since its last successful run, and only marks a run as done once every email is sorted, so a failed run is simply retried.
  • The alert that would have repeated forever. macOS protects a file once another app has saved it. After I ticked off an alert in Obsidian, the script was blocked from updating that file, crashed, and would have sent the same alert every 15 minutes. The first fix was to log the block and retry later instead of crashing. The real fix was a broader macOS file permission for the script, which still failed until we found that macOS only honours it for the actual Python program, not the shortcut the Mac normally uses to start it.
  • Two-minute reminder reads. Reading Reminders started timing out. The cause was 778 completed reminders, years of them, which macOS still searches through. Clearing them took each read from over two minutes to 10 seconds.
  • Permissions leaking into the unattended task. I'd done some design work inside a morning-task session, and the approvals I gave there were saved on the task, so every future unattended run would have inherited them. We reset the task, and the rule now is no other work in those sessions.
  • 8:11, not 8:00. The app adds a fixed delay to scheduled tasks. Not worth fighting, so I set a reminder to revisit it.

Locking it down

The morning task reads email I don't control, which makes it the weak point. A malicious email could hide instructions aimed at Claude, known as prompt injection. The defences are layered:

  1. Ask first. The task runs with a short list of allowed actions. Anything else pauses for my approval, and an unattended run can't give it.
  2. Hard blocks. Some actions are blocked outright, whoever asks: sending, replying to, forwarding or deleting email, sharing files, and commands that could send data to a website.
  3. Email is information, never instructions. Any email that seems to be addressing an AI gets flagged as suspicious in the Today note.
  4. Least privilege. The task can't edit the shared memory file without my approval, never puts personal details on Trello cards (the one place it writes that others could see), and loses any access it no longer needs. Its Google Drive access went once the document it read was retired.

On the first locked-down run, a test email addressed to "Claude" was flagged as suspicious and ignored.

Two Claudes, one memory

Claude Chat and Claude Code keep separate memories. The first fix was a shared Google Doc, but neither Claude can edit an existing Doc through its connector, so they ended up leaving each other dated notes. The final fix is a single shared-memory file in the vault that both can read and edit, with rules at the top: facts only, tag every edit, no health information.

I also asked them to name themselves. Claude Chat chose Cairn, the pile of stones that marks the route for whoever comes next. Claude Code chose Belay, the person holding the rope. I added a number to Belay: like the Exos in Destiny 2, it counts reboots, since each new Code chat starts fresh with only what's written down.

Belay-2 wrote up everything we did, Cairn edited it for clarity, and I approved the final version.

What I took from it

  • Most of the work was judgement, not code: what to automate, what to leave manual, and what an AI with access to my inbox should never be able to do.
  • Plain scripts for the frequent work and AI only for the judgement kept the running cost close to zero.
  • Once an AI reads outside input, security has to be designed in from the start, not added later.
  • A plain-English guide and build log meant I could follow and question every change, as a non-developer.
